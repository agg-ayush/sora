# Acrobat Sign v6 form prefill

- Creation: `mergeFieldInfo: [{"fieldName":"<existing-name>","defaultValue":"<value>"}]` on `POST /agreements`. `fieldName` must be a generated/authored form field, not a printed PDF label. `formFieldValues` is not a v6 creation property.
- In `AUTHORING`: `GET /agreements/{id}/formFields` works and each field's `defaultValue` already reflects create-time `mergeFieldInfo`, so read prefill back from there. The `.../formFields/mergeInfo` family (GET and PUT) is DRAFT-only on a live na1 tenant: in `AUTHORING` it returns 403 `AGREEMENT_NOT_IN_DRAFT_STATE`, despite docs implying AUTHORING support. Either create in `DRAFT` and do mergeInfo set/readback there before moving on, or stay in `AUTHORING` and verify via `formFields` `defaultValue`. Preview with `GET /agreements/{id}/combinedDocument?includeMergedFieldData=true`; then `PUT /agreements/{id}/state` `{"state":"IN_PROCESS"}`.
- `PUT /agreements/{id}/formFields` edits field definitions, only in `AUTHORING` (403 `AGREEMENT_NOT_IN_AUTHORING_STATE` otherwise). `IN_REVISION` is not full authoring.
- After send: read-only. `GET /agreements/{id}/formData?allowInProcessAgreement=true` reads in-flight data for the creator; there is no `PUT /formData`. `GET /members` gives participant status, not field values.
- Template choice: a library document with stable named fields (`GET /libraryDocuments/{id}/formFields`) for repeatable contracts; a transient PDF works if it carries Sign text tags or real AcroForm fields (converted on upload/send). Drawn boxes and underlines are not guaranteed named fields. Run the real PDF through `AUTHORING` and inspect names, assignees, `readOnly`, `contentType`.
- Leave signer name and signature date to Acrobat Sign's own fields (auto-populated, signer read-only). Title fills only if known. Do not claim sender values can or cannot override system fields without a tenant test.
- HelpX pages sometimes block extraction; cite archived Adobe-authored copies with their snapshot date.
