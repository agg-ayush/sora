# Hosting comparisons

Use for cloud-hosting vendor comparisons where availability commitments, cold starts, operating cost and backend dependencies affect an architecture decision. Cited briefs also follow `citations.md`.

## Procedure

1. **Diagnose reported slowness before blaming the platform.** Pull real request durations from the runtime logs first (Amplify: `aws logs filter-log-events --log-group-name /aws/amplify/<app-id> ... | grep -oE 'Duration: [0-9.]+ ms' | sort -n | tail`). Multi-second durations or hard-timeout values (exactly 30000 ms) point at app work blocking the request, such as a synchronous build on first load, which no platform move fixes. Card that as a separate app fix. A TTFB probe from a warm route does not reproduce what the user felt.
2. **Use only the evaluation axes the user cares about.** Do not invent weighting axes (geography, latency, contractual SLA) and let them drive the pick; confirm weights when unsure. A number stated for emphasis is not a hard target.
3. **Price every credible option, not the shortlist already in mind.** Dispatch a researcher with the full candidate list (current platform; AWS container, VM and serverless families; GCP Cloud Run; Vercel; Cloudflare via OpenNext; Netlify; Railway, Render, Fly) and an instruction to add anything credible that is missing. Required per option: cost for one environment and for both with formulas, streaming support, response, body and timeout caps, a verbatim SLA quote with URL, cold-start evidence, ops burden.
4. **Model environment parity explicitly.** Staging identical to prod doubles per-environment compute on container and VM platforms, while team-or-account-floor platforms (Vercel, Cloudflare, Netlify) often cover both under one floor. Show both columns.
5. **Apply the end-state filter.** Drop options with a hard conflict against a known later requirement (no streaming for a chat feature, response caps below document payload sizes) rather than planning a migration.
6. **Verify ownership of the hosting account before recommending it.** For Vercel, list the teams the user can actually see (Vercel MCP `list_teams`): a personal team, or a colleague's, is the wrong home for an org production system. If no org-owned team is visible, present the fork: get added to an existing org team, create one (cost and who pays), or pick another platform.
7. **Present** a compressed table (both-environment cost, streaming, SLA, the one catch per option), then a lean conditional on the open governance question, and leave the pick to the user.

## Evidence rules

- Read the AWS SLA index **and** the linked service-specific contract: an index listing can overturn the assumption that no SLA exists. Distinguish the percentage from its eligibility (region, AZ spread, healthy targets), measurement window, exclusions and service-credit remedy. Do not combine separate component SLAs into an end-to-end guarantee.
- Verify serverless runtime limits on the particular hosting product, not generic underlying compute docs. Community cold-start numbers are application anecdotes, not service percentiles.
- Separate build-machine RAM, execution-instance lifetime, request timeout, response and body limits and per-instance concurrency. Mark missing vendor specs as missing rather than importing limits from Lambda or containers.
- Model low-traffic container and VM costs with explicit operating hours and the baseline load balancer, public IPv4, provisioned memory, storage and variable LCU or traffic assumptions. Calculate with a tool and label minimum sizing untested until the app runs.
- Check current product eligibility before analysing architecture: a product may stay operational for existing accounts while rejecting new customers.
- A status-page feed may show only recent incidents or duplicate IDs after a migration. Inspect incident records and coverage date, deduplicate and distinguish regional, customer and product impacts. Never infer a 12-month availability percentage from examples.
- For cited briefs, pair URLs with verbatim fetched-page quotes in an evidence CSV and independently re-fetch decision-driving legal and price claims. Put source links beside each sentence; for coverage validators that split at punctuation followed by whitespace, write `claim [source](URL)[n]. Next claim` so adjacent claims count separately.
- If a legal URL's text extraction returns a navigational summary or empty shell, inspect the browser-rendered HTML before quoting a contractual percentage, and verify the exact defined-term wording and eligibility there.
- Cross-check a vendor's canonical pricing page against its detailed billing examples when regional egress basis differs (destination versus origin). Model the expensive plausible reading and ask the vendor to confirm billing rather than choosing silently.
- For confidential-document applications, check hosting terms for prohibited data classes (including financial and government identifiers) independently of technical upload capability, and flag a counsel or negotiated-terms gate when the contract forbids relevant data.
- For edge platforms, separate account or team minimums from per-project and per-seat fees; separate preview or branch deploys from production; separate build-minute meters from runtime CPU and memory. Check whether a Next.js adapter runs SSR in Workers, a regional Function or truly at the edge instead of inferring it from the product name.
- Read service-specific enterprise SLA text before general enterprise terms: a Workers runtime SLA can override a broader CDN uptime statement. Do not promote an enterprise percentage to a self-serve plan, or a marketing-page percentage to a legal commitment when the order-form SLA is unpublished.
- Reconcile contradictory CDN pricing pages against the account's billing mode and workload eligibility, especially when large-file distribution is excluded. For streamed legal documents distinguish buffered body caps, streamed-response caps, CPU time, wall duration, isolate memory and static-asset size.
