# Claude Code CLI, hooks, and troubleshooting reference

Use with [../SKILL.md](../SKILL.md). Consult the [current official CLI](https://code.claude.com/docs/en/cli-reference) and [hooks](https://code.claude.com/docs/en/hooks) references for version-specific syntax. Do not run example commands with a real credential in logs.

## Quick CLI map

| Goal | Invocation / flag |
|---|---|
| Interactive task | `claude 'task'` |
| Short non-interactive task | `claude -p 'task'` (`--output-format json` or `stream-json` as needed) |
| Continue/resume/fork | `claude -c`, `claude -r <id>`, or `--resume <id> --fork-session` in the relevant directory |
| Structured extraction | `-p --output-format json --json-schema '<schema>'`; parse `structured_output` |
| Streaming events | `-p --output-format stream-json --verbose --include-partial-messages`; `--input-format stream-json --replay-user-messages` for bidirectional input |
| Route/model | `--model <supported-upstream-id>`, `--effort <level>`, `--fallback-model <model>` (print mode) |
| Permissions | `--allowedTools <tools>`, `--disallowedTools <tools>`, `--permission-mode <mode>`, or consciously `--dangerously-skip-permissions` |
| Session scope | `--add-dir`, `-w/--worktree [name]`, `--tmux` with `--worktree`, `--session-id` |
| Context/config | `--append-system-prompt[-file]`, `--settings`, `--mcp-config`, `--strict-mcp-config`, `--agents` |
| Diagnostics | `claude --version`, `claude auth status --text`, `claude doctor`, `-d/--debug`, `--debug-file` |

`--bare` skips hooks, plugins, MCP discovery, and CLAUDE.md, and skips OAuth; it needs API-key auth or an `apiKeyHelper`. Do not select it for a workflow that relies on project instructions, hooks, or Teams OAuth. `--max-turns` and `--max-budget-usd` apply to print mode; only add a turn cap when expressly requested. `--no-session-persistence` is useful in CI. `--fallback-model` can change the served model on overload; verify the final model if that matters.

Tool permission syntax includes `Read`, `Edit`, `Write`, `Bash`, `Bash(git *)`, `Bash(git commit *)`, `WebSearch`, and `mcp__<server>__<tool>`. Read-only print analysis can use `--allowedTools 'Read'`. A print-mode writer otherwise needs sufficient permissions or it may do no work. Limit shell tools to the necessary pattern when possible.

In an interactive session, `/review` and `/security-review` initiate review, `/model` and `/effort` change model/effort, `/context` inspects context use, `/compact` condenses it, `/resume` switches session, `/permissions` inspects rights, `/mcp` inspects servers, and `/exit` closes the session. `Ctrl+C` cancels a response, `Ctrl+D` exits, `Ctrl+B` backgrounds a task; use `@path` for files and `!` for an explicit shell command. Check the live UI before sending shortcuts. Project `CLAUDE.md`, `.claude/rules/*.md`, `.claude/agents/*.md`, and `.claude/skills/` can change behavior; inspect these before asking Claude to work in unfamiliar projects. User-level analogues live under `~/.claude/`. Keep task-specific instructions explicit rather than relying on an unspecified memory.

## Authentication, routing, and model verification

- Teams OAuth/session tokens and TrueFoundry gateway tokens are distinct. When a parent process launches `claude` without an explicit child environment, it inherits any `ANTHROPIC_BASE_URL`/`ANTHROPIC_CUSTOM_HEADERS` and may charge the gateway instead of Teams. For Teams, pass a controlled minimal environment retaining required `HOME`/`PATH` and the credential through a **secret-safe channel**; omit TF routing vars. Never put the actual token on a command line that will appear in logs or `ps`. Confirm the effective route and model from response metadata, not merely the model spelling or CLI exit.
- **Never run Claude Code on the TrueFoundry gateway.** The TF anthropic-protocol route bills every Claude model as `anthropic-primary` at pay-per-token list price, so a machine-wide Claude Code managed hook (`config/claude-code/block-truefoundry-hook.sh`, installed to `/etc/claude-code/` or `/Library/Application Support/ClaudeCode/`) refuses any prompt whose `ANTHROPIC_BASE_URL` contains `truefoundry`, and `claude_orchestrate` refuses it too. Route Claude Code through `claude_orchestrate` with `model_provider=seatbelt` (primary) or `model_provider=fireworks` (fallback); for those routes unset ambient `ANTHROPIC_API_KEY`, `ANTHROPIC_API_KEY_BACKUP`, and `BACKUP_ANTHROPIC_API_KEY` in the Claude process. If a session reports the hook's block message, switch route; do not try to bypass the hook. Never assume an old note declaring subscription auth disabled on all Ubuntu hosts still applies. On devbox EC2 (`sora`), `saml2aws` is retired.
- Seatbelt's Teams route uses plain `claude-teams-group/...` model IDs, **not** names with `[1m]` appended. Check actual selected/modelUsage route and usage metadata; successful PONG alone does not prove who is billed. If process environment inspection is necessary, report only variable **presence**, not values. In particular, never print `/proc/<pid>/environ` wholesale.
- For Opus 5.5, use a supported Claude Code CLI (2.1.280+). Some flagged cyber requests can be rerouted to Opus 4.8; a per-session `--settings` with native `switchModelsOnFlag: false` pauses instead of silently accepting a reroute. It does not override the safeguard. Verify the served model from metadata; do not overwrite a global binary while other tasks use it.

## Hooks: avoid stale examples

Read the [official hooks reference](https://code.claude.com/docs/en/hooks) before editing. In `.claude/settings.json` or `~/.claude/settings.json`, `matcher` targets **tool names** (e.g. `Edit|Write` or `Bash`); optional handler `if` can inspect a tool-input pattern. A command hook receives JSON on stdin (`tool_input.file_path`, `tool_input.command`, `cwd`). `$CLAUDE_TOOL_INPUT` and `$CLAUDE_FILE_PATHS` are **not** valid current data sources. `${CLAUDE_PROJECT_DIR}` is the original project root, while `cwd` follows an active worktree. Do not copy the older `matcher: "Write(*.py)"` plus `$CLAUDE_FILE_PATHS` autoformatter or shell-grep guard: it is misleading and not a security boundary.

On `PreToolUse`, exit 0 with no output defers to normal permissions; exit 2 with stderr reason blocks. A structured decision can be returned as one JSON object with `hookSpecificOutput.hookEventName`, `permissionDecision`, and `permissionDecisionReason`. `PostToolUse` exit 2 gives feedback but cannot undo a write. Exit 1, missing scripts, invalid JSON, or timeout normally fails open; for a critical command/HTTP guard, `onFailure: "block"` (v2.1.295+) can fail closed. Test hooks with sample stdin before enabling; use short timeouts and don't claim a conditional Bash string filter is a security boundary. Useful events include `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `TaskCompleted`, `Notification`, `Stop`, `SubagentStop`, and `StopFailure`. Do not treat an LLM Stop hook as correctness verification: errors/interrupts do not trigger it, and continuation loops can result. Use deterministic tests/CI plus a separate verifier.

## Monitoring and failure recovery

- **Prompt submission:** A multiline `tmux send-keys` prompt submits each embedded newline. Save the whole task in `prompt.md`, then send a single-line pointer with `send-keys -l` and a separate Enter; or pass the prompt as an argument through `claude_orchestrate start`. Capture the pane to handle only dialogs actually present. The bypass warning defaults to No; workspace trust defaults to Yes on first visit. Never navigate blindly on fixed sleeps. Avoid bypass as root: CLI refuses it outright.
- **Platform logging:** `tmux pipe-pane -o -t "$SESSION" "exec >> '/path/to/tasks/task-id/tmux.log'"` on Linux/macOS only. Git-bash/MSYS tmux can crash its entire server on `pipe-pane`; capture the pane periodically instead and avoid `| tee` inside `new-session`. `tmux -L <socket>` sessions are invisible on the default socket; inspect process/parent socket before declaring a coder dead or starting another writer. Always clean up only the owned session.
- **Plugin state:** `claude_orchestrate start` can report success while tmux dies immediately with a blank pane and status stuck at `starting`. Inspect the actual binary resolved **in the pane's environment**, not only an interactive shell. A Hermes-managed Node install missing the Claude native postinstall can print `Error: claude native binary not installed`. `tmux set-option -g remain-on-exit on` before the launch can preserve that error for capture; repair the corresponding package's native postinstall only after confirming this cause. The plugin's TF route may inject auth only for its opus ID; other models can open a `Not logged in` prompt if tmux inherited no auth. Probe chosen route and ensure the intended session inherits it; do not put tokens into public tmux status dumps.
- **Wait cap:** Hermes deferred-tool calls can time out at ~420s. Keep `claude_orchestrate wait` <=360s; reissue if still working. Once an outcome token is written, the plugin may stop blocking even while later turns continue; capture pane/process and artifact status before finalizing.
- **Linux Bash preflight:** `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` can force bwrap even with `sandbox.enabled=false` (seen in Claude Code 2.1.284). A PATH with nonexistent macOS entries on Linux can fail before Bash executes. Use a process-scoped PATH of trusted existing Linux directories and prove Bash works with `pwd`; check only that provider credential variables are absent from the Bash child. Ubuntu 24.04 AppArmor may deny unprivileged bwrap uid maps. Confirm with a minimal bwrap probe; with host-owner approval use Ubuntu's packaged `bwrap-userns-restrict` profile rather than disabling AppArmor, turning off scrubbing, or using an unconfined profile. Do not restart unrelated sessions. A successful Claude CLI exit when its Bash tool failed is not a successful preflight.
- **Dependencies:** Parallel first-time `npx <tool>` installs can race on shared `~/.npm/_npx` (`ENOTEMPTY`); install the tool once ahead of batch. A backgrounded one-shot `npm install` can leave partial/prod-only dependencies, after which `npx` floats an incompatible test runner and generates false React/vitest failures. Confirm project dev binaries in `node_modules/.bin`, use the repo's locked install (`npm ci --legacy-peer-deps` only if that mirrors its CI), and re-run tests independently before blaming Node or code.
- **Orphan print processes:** A Hermes background terminal handle can be lost after a session boundary, leaving a live `claude -p` child. Check process and remote branch/CI artifacts before killing or relaunching. On Windows git-bash, `taskkill //PID` path-mangles; use `cmd.exe /c "taskkill /PID <pid> /F"` only for a confirmed orphan that you own.

## Completion check

1. Confirm the intended model/billing route where relevant, without exposing credentials.
2. Check the actual Claude process/session, `status.md` and `result.md` (if used), expected files, and git diff; identify unresolved questions or exited/failed states.
3. Run tests/build independently outside Claude, verify the right dev dependencies and CI setup, and inspect review findings; don't substitute a generated report for actual execution.
4. Stop only owned sessions; keep needed worktrees/artifacts for review and report limitations plainly.
