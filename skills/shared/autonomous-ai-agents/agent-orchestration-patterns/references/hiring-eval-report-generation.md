# Hiring-evaluation reports and reviewer UX

Render structured dossiers with a deterministic template/script. Use a small LLM subtask only when the summary needs judgmental rewriting; give it the source, a concrete before/after example and a no-unexplained-jargon constraint. A missing delegate artifact is not completion: inspect progress, time-box it, and verify the produced file.

Give each item a plain-English collapsed score/takeaway and an expandable evidence view. Remove internal pipeline IDs from prose but retain the candidate's actual decisions and reasoning. Parse the *observed* transcript formats rather than assuming one role marker; test each parser against every item. A transcript with no reliable role boundaries is **unverifiable provenance**, not evidence by itself that anyone fabricated the work. Expose this limitation to the reviewer and request the raw export if available.

Every quote needs a provenance field: candidate turn, agent turn, evaluator commentary, or **unknown/unverified**. Match a source by an exact quoted span and turn boundary against the raw transcript/log; a missing substring can result from truncation, normalization or paraphrase and must never be labeled `evaluator` automatically. Treat evaluator reasoning fields as evaluator voice only when the generating schema confirms that provenance. Do not present a paraphrase as a verbatim candidate quote. Show speaker badges and source location so a reviewer can audit them.

Map internal candidate keys to display names from the authorized roster once, propagate the mapping through index, detail pages, decisions and all generator scripts, then rebuild and inspect generated outputs. Keep notes and decisions in a durable server-side store; give each note a stable ID, item ID and timestamp, and separate tooling errors from candidate findings. A selection popup should clamp to the viewport, flip above when needed and reposition on selection/scroll/resize/zoom; manually exercise these states.
