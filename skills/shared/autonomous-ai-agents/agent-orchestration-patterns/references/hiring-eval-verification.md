# Hiring-evaluation verification and cost

When a lossy `.md` transcript lacks write/tool events, inspect the raw structured sibling (if present) before concluding that no work occurred. Count the actual event types and payloads without printing candidate secrets. A raw log corroborates **recorded activity**, not independent authorship or provenance; reproduce the submitted build/tests on a controlled environment and distinguish environment drift from a contradictory claim. Prompt polish is not proof of who wrote it. State the observed evidence, what remains unverified, and what follow-up could resolve it.

After a judge/rubric change, inspect the per-dimension score distribution and the aggregator's explicit `abstain_reasons`, rather than inferring gate causes from missing per-item status. Ceiling clustering is a calibration prompt, not proof a strong candidate was scored falsely. Compare known anchor examples before and after, including weak/strong cases; track changes on the existing evaluation issue.

For cost, locate the actual run ID and inspect every transcript belonging to it. Determine whether `total_cost_usd` is **per-turn/incremental** or cumulative/duplicated before summing; deduplicate copied transcript segments. Distinguish successful-run cost from **total spend** across failed/retried runs; excluding charged failed attempts understates the latter. An empty newest directory or `$0` result is not evidence work was free. Report the accounting scope, exact run set, per-item costs and any missing usage records; do not invent current model prices to fill gaps.
