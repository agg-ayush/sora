# Claude orchestrate: interactive permission menus and launch failures

A session frozen at `starting`/`investigating` with no artifact may be showing Claude Code onboarding, project trust, read-outside-workdir, or permission-bypass menus. Inspect the actual tmux pane and highlighted option before declaring death; text steering does not necessarily navigate a TUI menu. Do **not** send an empty steer as 'Enter' or assume `Down` is always the allow option. Only approve a project or bypass permissions when explicitly authorized and after checking the path/scope; unattended bypass is not an automatic setup step.

For an isolated `CLAUDE_CONFIG_DIR`, use the current Claude Code documentation and an authorized disposable directory to prepare required first-run state. Test a *fresh* disposable config path, never `rm -rf` a live or possibly reused config directory. If a menu is present, choose using the actual highlighted options and verify the session resumes and writes its expected artifact. A missing tmux pane with null outcome is evidence of exit, but also inspect the plugin status/log for a concrete cause before calling it a crash.

Retry ladder: capture pane/log/workdir first; make one bounded retry of the same unit with a changed relevant parameter when supported (effort, corrected config or path). If the executor may be at fault, test its installed CLI standalone with a harmless probe, then inspect plugin invocation syntax and model identifier. Do not assume a particular engine has a permanent launcher defect from one case. Switching a paid provider/permission mode requires the applicable authorization. If launch keeps failing, use an authorized fallback with one writer on the same preserved worktree; report actual checks performed rather than a plausible result.
