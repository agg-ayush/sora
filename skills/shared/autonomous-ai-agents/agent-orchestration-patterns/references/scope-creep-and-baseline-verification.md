# Scope creep, base failures, and stale test artifacts

Compare the PR's exact merge-base-to-head diff **and the worktree's uncommitted changes** to the accepted design, including behavior, not only filenames. Investigate any unplanned edit before accepting it. Do not restore a whole file just because its name is absent from a plan—legitimate hunks can share it. Separate an independently owned bug into a tracked task without destroying a worker's dirty work; involve the owning worker for code changes.

For a red check, record the base SHA and reproduce the **same command, environment and failure mode** in a clean detached baseline worktree. Compare base CI history as well as local runs. Red on both is not automatically 'safe' or non-blocking: confirm the same underlying cause, current base policy and whether the PR exacerbates it; track it and leave the merge gate explicit. A shared `node_modules` symlink may be a useful optimization but is not a clean baseline if package/dependency versions differ—install/rebuild the right revision where necessary. Clean up only the verification worktree after checking for changes.

When a supervisor rerun disagrees with a worker's passing run, inspect what CLI binary and env each command actually used. Build the branch version, invoke it by an explicit path/`PATH`, and compare to the installed version. Some harnesses strip an override env var; inspect harness source. Record exact binary paths and exit codes; one passing branch run means the earlier installed-binary result may have been stale, not that every other gate is green.
