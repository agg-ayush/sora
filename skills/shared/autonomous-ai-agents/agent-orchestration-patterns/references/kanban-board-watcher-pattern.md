# One background watcher per kanban board

For a requested ongoing board watch, use one bounded watcher with an explicit baseline, board name, event condition and timeout. A delegate's *own* completion differs from its shell subprocess/timer exiting. Before re-arming, list active delegates and stop duplicate watchers; update the baseline from the board. Re-arm when continued watching is authorized and still needed, **not** before handling a stop request or urgent user instruction. A leaf delegate cannot simply spawn another leaf as a self-renewing chain; the parent manages re-arming, or use a documented durable watcher where persistence is required.

A one-shot 'tell me next change' watcher exits after one event. A continuous watch must continue after events or be re-armed by the parent; state the expected behavior in the goal. Never accept a natural-language watcher claim that a task disappeared or a PR merged without querying the exact board card and GitHub PR/head. A heartbeat from a supervising T2 does not prove its child is progressing; read the child pane, commit age and actual test/check state.

An idle T2 and a clean/green PR mean **investigate why it is waiting**, not 'merge now.' Verify review verdict and required checks on the current SHA, merge authorization for this workstream, dependencies and cutover policy; only the authorized merge owner proceeds. If a PR remains open through several polls, steer with a concrete missing gate or rebase action. After a confirmed merge, close the authorized board card and stop only the owned idle sessions, preserving any dirty work or active unrelated sessions.
